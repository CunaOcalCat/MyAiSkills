## 🛡️ Strict Source-Code Verification (v5)

코드를 병합·수정·포팅할 때 AI가 **소스코드를 직접 확인하지 않고 파일명이나 함수명만 보고 추측(환각)하여 코드를 작성하는 현상을 원천 차단**하는 규칙입니다.

* **한글 버전:** [`strict-source-verification.md`](./strict-source-verification.md)
* **영문 버전:** [`strict-source-verification-eng.md`](./strict-source-verification-eng.md) *(LLM 지시 준수율 최적화)*

### 주요 방지 및 강제 기능
* **코드 작성 전 강제 검증 (`[VERIFICATION]`):** 코드를 쓰기 전에 실제 읽은 파일, 함수 시그니처, 반환 타입, 누락된 요소를 먼저 출력하고 불확실한 부분이 있으면 즉시 작업을 중단합니다.
* **추측·생략·임의 수정 금지:** `// ... 기존 코드 생략 ...`, `TODO` 가짜 구현, 요청 없는 내부 로직/라이브러리 교체를 차단합니다.
* **대용량 파일(500줄 이상) 안전 처리:** 파일 전체 덮어쓰기를 금지하고 부분 수정(Diff)만 허용하며, 공유 상태 변수의 파일 내 모든 참조 위치를 먼저 검색하도록 강제합니다.
* **이종 언어 및 프레임워크 포팅 검증:** C++ ↔ C# 등 언어나 프레임워크가 다를 때 미설치 라이브러리 임의 도입을 막고, 언어·OS 간 동작 차이(메모리, 인코딩, 레지스트리 뷰 등)를 사전에 명시하게 합니다.
* **대량 데이터 조용한 누락 방지:** 30개 이상의 반복 항목(설정값, 레지스트리 등)을 옮길 때 30~50개 단위로 배치 분할하고, `완료 개수 / 총 개수`를 대조하여 100% 일치할 때까지 완료 선언을 금지합니다.

## 적용

사용 중인 코딩 에이전트의 규칙 폴더에 원하는 버전(한글 또는 영문 중 1개)을 넣어 사용하세요.

> **팁:** 한글판과 영문판을 같은 규칙 폴더에 동시에 넣으면 토큰이 중복 소비되므로 둘 중 하나만 활성화하는 것을 권장합니다.
